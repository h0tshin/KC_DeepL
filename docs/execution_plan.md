# KC DeepL Execution Plan

## Phase 0. 기반 구축

- SwiftPM 프로젝트 생성
- 앱/코어/테스트 타깃 분리
- Codex Run 버튼용 `script/build_and_run.sh` 작성
- 첨부 UI 스크린샷을 `references/screenshots/`에 보관

완료 기준:

- `swift test` 통과
- `./script/build_and_run.sh --verify`로 앱 프로세스 실행 확인

## Phase 1. 목업 UI 완성

- DeepL형 2패널 메인 화면 구현
- 상단 모드 바와 언어 전환 구현
- 오른쪽 도구 패널 구현
- 설정 창 구현
- 화면 캡처 진입 목업 구현

완료 기준:

- 앱 실행 시 메인 창이 전면에 표시
- 설정 창에서 모든 카테고리 이동 가능
- 고급 설정에서 공급자/모델/API 키 변경 가능

## Phase 2. 번역 기능 연결

- Gemini `generateContent` 호출
- 번역 프롬프트 생성
- 오류 상태 표시
- 번역 기록 메모리 저장

완료 기준:

- 입력 텍스트가 Gemini 모델로 전송되고 결과 표시
- API 오류와 빈 입력 오류가 UI에 표시
- 기록 토글이 켜져 있을 때 최근 기록 패널 갱신

## Phase 3. 시스템 통합

- 전역 단축키 등록
- 선택 텍스트 읽기
- 플로팅 번역 창
- 로그인 아이템 등록
- 앱별 단축키 차단

완료 기준:

- 앱 외부에서 선택한 텍스트를 단축키로 번역
- 설정의 차단 앱에서는 단축키 미동작

## Phase 4. 캡처/OCR

- 화면 캡처 권한 요청
- 캡처 영역 선택 overlay
- Vision OCR
- OCR 결과 자동 번역

완료 기준:

- 캡처 영역의 텍스트가 원문 필드에 삽입
- 권한 없음/텍스트 없음/다국어 OCR 실패 상태 처리

## Phase 5. 파일 번역

- 드래그앤드롭 파일 수신
- 지원 확장자 검증
- 텍스트 추출 또는 Gemini 파일 입력 전략 확정
- 번역 파일 다운로드 위치 설정 반영

완료 기준:

- 지원 파일 번역 요청 생성
- 실패 파일과 성공 파일을 분리 표시

## Phase 6. 배포 준비

- UserDefaults 기반 API 키 저장
- 앱 아이콘과 번들 메타데이터 정리
- Notarization 준비
- 개인정보 안내 작성

완료 기준:

- 릴리스 빌드 생성
- Gatekeeper 검증
- API 키가 저장소에 남지 않음

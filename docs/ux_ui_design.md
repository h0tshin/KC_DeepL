# KC DeepL UX/UI Design

## 1. 디자인 원칙

- 빠른 번역 앱이므로 첫 화면은 설명 페이지가 아니라 실제 번역 작업 화면이다.
- 다크 테마를 기본으로 하되 macOS 시스템 컨트롤과 접근성을 해치지 않는다.
- DeepL 레퍼런스의 2패널 구조, 상단 모드 바, 오른쪽 도구 패널, 별도 설정 창을 따른다.
- 기능 소개 문구보다 작업 가능한 컨트롤을 우선한다.
- 화면 캡처 OCR은 다음 단계 기능이지만 PDF 파일 번역의 스캔 페이지에는 Vision OCR과 품질 경고를 제공한다.
- 라틴 UI/본문은 Barlow, 한글은 Noto Sans KR을 함께 cascade하고 코드·고정폭 표기는 D2Coding을 사용한다. 번들 등록 실패는 화면을 막지 않고 시스템 글꼴로 대체한다.

## 3. 오른쪽 최근 기록 패널

- 표시 방식: 상단 툴바 버튼으로 토글
- 너비: 약 280pt
- 최근 번역 3개의 결과와 엔진·모델 정보를 표시한다.
- 동작이 없는 격식·스타일·용어집 컨트롤은 제공하지 않는다.

## 4. 설정 창

- 콘텐츠 크기는 760×520pt로, 이전 1100×720pt 대비 면적을 약 절반으로 줄인다.
- 사이드바는 164pt, 상세 영역의 여백은 20pt로 맞춘다.
- 상세 콘텐츠는 536pt, 항목명은 112pt로 통일하고 항목명과 컨트롤 사이에 12pt를 둔다. 스크롤바가 생겨도 열의 위치와 너비를 유지한다.

왼쪽 사이드바:

- 일반
- 키보드 단축키
- 손쉬운 사용
- LLM 번역
- LLM Live
- 파일 번역

오른쪽 상세:

- 제목과 설명 아래에 컨트롤을 정렬하고, 섹션은 간격으로 구분한다.
- 선택 메뉴와 API 입력란은 남는 너비를 채우며, Live의 두 언어 입력란은 나란히 배치한다.
- 단축키 입력란은 180pt로 통일하고, 슬라이더의 값은 오른쪽 끝에 정렬한다.
- 긴 설정은 세로로 스크롤하고, 카테고리를 전환하면 상세 영역의 맨 위를 표시한다.
- LLM 번역 탭은 번역 방식, 세부 모델, API 키, 자동 번역, temperature를 배치한다.

## 5. 화면 캡처 UX

현재는 화면 캡처 컨트롤과 단축키를 제공하지 않는다. 실제 OCR 결과를 원문으로 입력할 수 있을 때 아래 흐름을 제공한다.

추후 구현:

1. 화면 녹화 권한 확인
2. 전체 화면 overlay로 영역 선택
3. Vision OCR 수행
4. 원문 필드 삽입
5. 자동 번역 실행

## 6. PDF 파일 번역 UX

1. 상단 `파일 번역` 모드에서 PDF를 선택하거나 작업 영역으로 끌어다 놓는다.
2. 왼쪽 PDFKit 미리보기에서 원본을 확인하고 오른쪽 inspector에서 Apple, Codex 또는 Gemini API 엔진과 모델을 선택한다.
3. 분석 중 발견한 OCR, 낮은 신뢰도, 복잡한 배경, 링크/기존 주석 중첩, 안전한 좌표 복원 guard를 통과하지 못한 페이지 경고를 번역 전에 표시한다. OCR 누락 가능성이 있으면 확인 체크박스를 선택하기 전까지 시작 버튼을 비활성화한다. MediaBox 원점이 (0, 0)이고 회전이 0°/90°/180°/270°인 페이지를 지원하며, 조건을 벗어나면 원격·유료 엔진 호출 전에 중단한다. 비영점 CropBox의 90°/270° 페이지는 지원한다.
4. 번역 중 페이지 진행률과 취소 버튼을 제공하고 입력·엔진·저장 설정 변경을 잠근다.
5. 완료 후 상태는 픽셀 동일성을 암시하지 않는 `출력 PDF 구조 재검증 완료`로 표시한다. 원본/번역본 segmented picker로 결과를 비교하고 PDF 열기/Finder 보기 동작을 제공한다.
6. 원본 비파괴, 번역 레이어 방식, 원문 검색 데이터 잔존과 시각적 동일성 한계를 inspector에 상시 표시한다.

## 7. 색상과 타이포그래피

- 배경: 어두운 중립 회색
- 강조: macOS system blue
- 성공/보안 상태: system green
- 텍스트: primary/secondary/tertiary semantic foreground
- 입력 힌트: 26-30pt, 번역문: 25pt
- 설정 제목: headline
